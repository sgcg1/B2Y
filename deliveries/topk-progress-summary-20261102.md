## 2. 当前实现与版本身份

最新阶段实验实际运行的TileOPs提交为7247ad4f355c62a8679dcdc8fdf182c0b219db5e，kernel SHA-256为987da9f9d314f8744bef05a628e60a14b88e63db320374f36a3b6411ce5eb2e3。之后的设计文档提交不等于新的内核优化版本。

当前实现保留以下机制：

- 精确FP32有序键及逐轮radix选择；FP16粗键用于部分规格的前置筛选，不代替最终FP32比较。
- 容量2048的候选键/索引双缓冲；超过容量仍完整计数并走精确重扫，2048不是输入规模上限。
- H128 grouped scan，用分组前缀和替代原来的单线程256桶扫描。
- 按实际Vector核数安排worker；Decode单行当前仍由一个worker处理。
- 保持NaN、±0、窗口、哨兵和同分取较小绝对索引的规则；输出槽位无序，选中集合确定。

H256 grouped scan曾出现253个未填槽位，尚未修复，当前不放行。不能把H128通过描述为H256已解决。

## 5. 最新Decode阶段定位

本轮固定规格为R1/N16384/K2048/W1/H128，coarse=true。输入及生产生成源码与已保存Decode记录匹配。

| 区间 | 中位耗时 |
| --- | ---: |
| 第0轮histogram | 55.983μs |
| 第0轮compact | 73.2385μs |
| 以上两段同次相加后取中位数 | 129.2055μs |
| 全部五轮scan同次合计 | 7.345μs |
| quota归零后的第4轮 | 1.983μs |
| 最终tie与收尾 | 9.589μs |

首轮两段占同次已测阶段总和的中位比例81.039%；分母是插桩后的阶段区间总和，不是无插桩生产总耗时。不同区间的中位数也不能直接相加当作一次运行的总时间。

候选轨迹为16384→835→835→25→0；本次没有2048缓存溢出。第1轮没有新增输出，但细化了FP32前缀，不能视为无用。第3轮之后quota归零，第4轮和最终tie段仍有可见成本；它们是次级优化候选，不能无条件删除tie。

主要瓶颈已经定位到“首轮全窗处理”这一级；尚未独立证明其中原子竞争、键转换、分支或访存各自占多少。

## 6. 测量扰动与结论边界

| 版本 | 完整事件中位数 | 相对production |
| --- | ---: | ---: |
| production | 162.7365μs | — |
| traced | 164.1345μs | +0.86% |
| fenced | 166.4200μs | +2.26% |
| timed | 168.6810μs | +3.65% |

4个版本分别用于区分状态快照、完成屏障及计数器记录成本。本地重算了全部汇总和50组27区间的时间戳关系；主要VF算术体保持一致，状态更新VF另含诊断快照写入。

阶段数据足以安排本次Decode的优化优先级，但不是无插桩阶段成本的精确分解。0.1～0.5μs短区间尤其受到观察成本影响。报告中的stage_profiling_accepted=false保留，不因status=completed自动接受。

本轮报告随机与全相等输入检查通过，不是又执行了一轮完整14项契约。也没有同轮CANN、Prefill阶段轨迹、独立进程重复或完整负载/频率时序，不能据此宣布全规格性能结论。

详见[Decode阶段完整分析](../experiments/topk/20261102-stage1-decode-163258/analysis.md)。

## 7. 后续工作优先级

| 顺序 | 待验证方法 | 关键判断 |
| --- | --- | --- |
| 1 | 首轮专门化、粗键显式复用 | 减少重复转换和动态round判断；编译器可能已消除部分重复，需实测 |
| 2 | 缓存uint8粗键供compact复用 | Decode额外16KiB/worker；有望减少第二次FP32全窗读取，但需计入UB写读和大边界桶退化 |
| 3 | 分片histogram及分片compact | 先试4片计数bank约4KiB；核对归并、VF边界、布局和精确候选计数 |
| 4 | Decode仅首轮跨核、后续单核精筛 | 先评估2/4/8个worker的launch、归并、GM通信与路由成本 |
| 5 | quota归零后条件跳过 | 独立比较，保留需要tie的场景，不预告可省全部实测时间 |
| 分支调查 | Prefill溢出与行耗时分布 | K1024当前走直接FP32路径，应与K2048粗筛分别补证据 |

扫描、单个大Prefill尾部调度与无证据扩大缓存暂不作为主线。原第4.2节中的“任何原子抢位都不允许”也已收窄：必须避免以抢位决定阈值同分者保留谁，但已确定全部入选者可以原子分配无序写入槽位。

各候选先做CPU/生成代码与小规格设备检查、固定输入无插桩A/B；快速淘汰无收益方案，再对有希望的候选完成14项契约、独立重复及128行/完整Prefill回归。扩展种子、分布和窗口，避免对单一输入过拟合。新的阶段插桩必须对应新版本与明确映射，不绕过现有工具的SHA限制。

完整方案、成本模型和历史判断修正见[优化路线复评](topk-optimization-roadmap-20261102.md)。
