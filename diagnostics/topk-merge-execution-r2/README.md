## r1结果与本轮变更

r1两档完成编译，但编译器报ThreadSync：分歧if内部的冲突无法由外提barrier解决。守卫拒绝执行，所以没有设备归并正确性或耗时，不能称为算法跑错或性能差。原始结果已独立归档。

r2保留同一算法、输入、批宽和计时方法，仅改设备控制/地址表达：side用有界整数划分；头块地址显式有界，填充值写到UB在分歧条件之外；排名先写线程局部变量，再在有效性分支之外保存左排名；二分共享读索引显式有界。合法输入下这些边界裁剪不改变算法数据，尾部无效元素不参与排名。没有添加T.assume、关闭诊断或把警告当成已证明的误报。

修改后的实际内核AST仍通过64项CPU检查，包含输出唯一写与每批指针。但CPU顺序执行不能证明SIMT同步安全，仍须本轮现场编译与设备验证。若ThreadSync仍出现，脚本继续拒绝执行，回传日志分析，不原样重跑。

## 本轮新增实际设备工作

输入是两条**CPU预先排序、索引互不重复**的有序段，每段最多2048项，元素为完整uint32分数键+int32原绝对索引。CPU没有提供归并前缀、最后一项、来源标签或消费数给设备；它只保留独立全排序答案用于核验。

每个设备block处理一组输入，连续归并至多2048项：

1. 各读取左右最多R个头元素到UB。
2. 对每个头元素，在另一头段二分统计更优元素数；其输出排名为本段位置+该数量。同分按较小绝对索引优先，uint32键以位重解释比较，不误用signed排序。
3. 排名小于本批输出数的元素直接写唯一目标位置，无scan、归约API或原子申请槽位。
4. 左段计算出的排名严格递增，对它二分得到本批左消费数；右消费数=本批输出数−左消费数。按实际消费数推进，写出每批累计指针trace。

与上一轮按“最后一项的键”定位相比，这里使用本轮设备已经产生的单调排名数组定位；同属二分消费数方法，不读取CPU提供的归并结果。R128连续16批，R256连续8批，不只测试第一个前缀。

正确性依据：头块之外的项在本段已有R项排在其前，不能进入下一批前R；有序段中元素的全局头块排名可由另一段更优数量确定。输入索引唯一，因此每个输出排名唯一。没有动态共享内存散布写，左排名由本lane写固定位置，减少不明确的共享写依赖。

这是**SIMT并行二分排名归并候选**，没有假装调用了已验证的原生SIMD merge指令。它的比较次数约O(R log R)/批，控制与重复头块载入可能很贵；本轮正要测量这些成本。若明显超预算，应否决/更换归并方法，而非以“可运行”为由继续完整TopK。

## 正确性验证

32组规格级输入，两种R各执行3次。比较全部2048项输出键、索引、每批左右累计消费数及累计输出数，检查输入未被修改。覆盖：严格交错、全部来自左/右、同分混合索引、空段、单侧为空、短尾、uint32符号边界、输出上限0/1/127/128/129/255/256/257/511/512/513/2047/2048和随机。

CPU oracle直接对带来源的输入并集做一次独立全排序，不使用排名归并。另在本地解释执行**实际kernels.py的AST**，32×2=64项全部通过，核验边界、每批指针、完整结果以及每个合法输出只被归并写一次。该检查不代表NPU已编译或执行；设备结论待本轮回传。

## 单节点设备时间

只有正确性通过后，才为B=1编译同一算法，测严格交错的两条2048项输入→前2048项，分别R128/R256：3次预热、5个独立单调用profiling窗口；每次前在窗口外执行1GiB int32驱逐并同步。复用已验证的原始设备任务解析，要求1个实际任务，保留全部样本与原始证据，不使用Event或主机墙钟替代。

测量包含输出初始化、归并、消费数更新、指针trace写出，不包含局部排序或其他两个全局归并节点。两个批宽的工作相同而批次数不同，可观察控制组织的成本，但不能由二者差值精确断言某个同步的独立耗时。

**禁止用10.639μs除以此微基准耗时宣称M达标。** 这是一个两路归并节点，不是完整16384输入TopK；也不能机械乘3来预测整个M，因为真实数据驻留、缓存和依赖不同。仅5个单节点样本用于初步能力/成本判断，不是三轮正式全算子稳定性能结果。
