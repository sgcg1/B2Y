# A1同步分析：元素单位缺陷与最小候选补丁

## 当前结论

现场同步分析源码与官方0176ba14逐字节相同（SHA见identity.json）。PointerAccessIsDisjoint的touched来自BufferLoad/Store或address_of路径，索引按各自元素大小记录；该函数未统一dtype单位，而普通FindConflict路径另有乘dtype.bytes()处理。故这条指针区间检查存在可构造的混合单位缺陷，不只是“可能有额外开销”。但尚未直接导出生产三个警告的访问对，不能把全部A1警告标成误报。

固定A1 C++ SHA41f977258da77d3a2bcc43d0327891381317492619abfd4eb6999fea86435941中，uint8粗键缓存字节范围[0,16383]，hist的int32元素范围[12288,12544]对应字节[49152,50179]，state[12936,12942]对应[51744,51771]，prefix[12944,12946]对应[51776,51787]。缓存与这些区域真实不相交；直接比较元素下标会出现伪重叠。cache写入由tile*128+lane唯一归属，VF3写入、VF8读取。具体线程屏障及原子依赖仍需结合完整pass IR验证，不能用这些区间代替整个kernel的同步证明。

反方向也有风险：uint8元素400与int32元素100实际都涉及字节400，直接比较下标会误判不相交。因此修正必须统一单位，不能靠布局挪动或强制放宽同步检查。

## 候选补丁

pointer-byte-ranges.patch仅修改官方src/ascend/transform/thread_storage_sync.cc中的PointerAccessIsDisjoint：整数区间检查后，将两侧inclusive元素区间转换为int64字节区间，末端加元素宽度减1，保留原有未知/无界区间保守处理、约束重命名和分析流程。

已完成：按现场源码SHA冻结；git apply --check通过；4项CPU算术检查通过，其中覆盖16种元素宽度组合×1024对位置。test_ranges.py仅验证区间数学及静态布局，不调用TVM C++，不能写成编译器测试通过。

未完成：C++编译、TVM约束求解回归、向量/符号/负偏移边界验证、使用补丁重新降低A1、完整设备正确性及性能回归。补丁尚未安装、尚未提交上游，也不是正式修复。没有修改TileOPs生产源码或服务器环境。

## 成本和下一步

单纯把cache搬入另一VF不能保证消除混合单位误判，还可能引入额外调用或重读。将uint8改成uint32会使缓存扩大4倍，是另一种性能方案，不应伪装成零成本修复。共享编译器安装不在修改范围内。

A1事件收益目前约1%，不足以无条件投入一轮完整工具链重建。保留这份可审阅补丁，A1仍默认关闭且不接受。继续主线时优先独立A2的int32分片histogram，避免让优化进展依赖这份未编译的后端补丁；若后续选择验证编译器补丁，必须在私人副本编译并记录新工具链身份，重新建立对照，不混入旧测量。

本轮没有新的服务器执行指令，不需要重复最小复现或A1 r2。后端源码参考：https://github.com/tile-ai/tilelang/blob/0176ba14/src/ascend/transform/thread_storage_sync.cc
