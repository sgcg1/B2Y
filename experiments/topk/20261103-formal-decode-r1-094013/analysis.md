# 正式Decode基线与设备拆解：差距主要在kernel内部

结论：第一进程完整采集，第二进程因部分流水记录停止；不能声称两轮完整正式复现。已有完整同轮结果显示随机r3约0.105–0.107x Ascend C（设备包络），而完整调用事件约0.213–0.216x。两口径均合法但含义不同，必须同时标注，不混用旧基线。最终接受仍false。

倍率统一为CANN耗时/TileLang耗时。设备包络从r3首kernel开始至末kernel结束，包含中间gap；完整事件包含API提交及GE静态模型调度等作用。不能将事件约0.21x写成设备计算约0.21x，也不能机械用两种采样相减分配host开销。CANN输出FP32 values+INT32 indices，这是已接受功能差异，r3仍强制小索引tie。CANN校验合法唯一索引、FP32 gather及top-score多重集合，不虚构其稳定tie语义。

GE模型按固定[1,16384]/K2048、largest=true、sorted=false、sort_policy=0、dim=-1、must_keep_origin_dtype构建。报告记录源文件身份、模型SHA/大小及ACL实际I/O描述；OM二进制本体未回传，不能冒称独立重算模型SHA。工具和源身份匹配、冻结生成码匹配；原始CSV全部大小/SHA核对，第一进程12个profile的同次分组、包络及倍率均独立重算。

## 随机输入的实际设备成本

以下采用random-20261030第一进程。各阶段中位数独立呈现，不将它们相加冒充某次调用；占比按同次duration/envelope先计算再取中位数。

| 阶段 | 中位数 μs | 同次包络占比中位数 |
| --- | ---: | ---: |
| hist | 11.7020 | 13.28% |
| prepare | 28.7685 | 32.59% |
| compact | 15.9780 | 18.13% |
| finish | 31.6065 | 35.89% |

四kernel包络中位数88.0995μs；三gap同次总和中位数0.066μs。第二seed结构一致。profiler可能扰动时序，此处不是无profile的逐段精确分摊，但没有证据把主要差距归给kernel间空隙。减少launch可能影响完整事件，但不能假设能抹掉这约88μs设备计算。

全同分溢出finish约529.341μs，占同次包络中位比例90.53%；小边界同分prepare约25.811μs，占37.66%。不同分布瓶颈不同，不能只围绕固定随机输入优化。

## 为什么差距仍大

1. prepare存在可确认的串行结构：T.Parallel(P)仅P个线程处理分块偏移，每线程对前面的分块再串行遍历256桶，P4最重线程最多768次桶读及相关判断。28.7μs是整个prepare测量，尚未单独证明这段循环占全部成本，但它是最直接的可改造结构。它不是探针中只做全局阈值的简单merge。
2. finish的小候选路径仍为8轮、每轮8次VF，初始化/收尾后约67次VF调用；这些是单kernel内部VF调用，不是67次kernel launch。容量路由没有消除quota提前归零后的轮次框架。未记录具体何轮归零，不能承诺直接省掉四轮全部成本。
3. hist仍是SIMT逐元素共享原子，compact也是逐元素筛选及散写。前期A2分bank回退说明争用不是“增加分片就解决”的问题；当前hist单段11.7μs已大于CANN完成整个TopKV2的9.223μs。最终指令/吞吐尚未采集，不把GM表达式重复当成实际HBM事务次数。
4. CANN公开源码具备寄存器批量统计、UB数据搬运及规模模板，但当前安装二进制具体路线未还原，不把公开模板直接当本轮实际路径。随机有限全窗差距也很大，不能只归咎确定性/NaN/窗口契约。

## 1.0x目标的预算约束

在其他阶段成本保持不变的乐观模型中，将prepare与finish整个移除，按每次包络减去这两段再取中位数，两个随机seed仍需27.7345/27.6470μs，只相当于0.3325/0.3403x Ascend C。该模型不是可执行算法，只用于说明：只优化两个最大段不足以达到1.0x，hist和compact也必须改变执行效率。不能把四段各自最好值拼成达标预测。

## 第二进程为何失败、哪些证据仍有效

第一进程有4输入×3版本×50=600事件及12完整profile。第二进程有首随机输入3版本×50=150事件，r3事件约0.2091x Ascend C；baseline profile完整，但r3仅239条kernel记录，开头Block Num为1/4/1，末尾完整。原严格解析器因此报Partial pipeline capture，后续CANN profile及其他输入未执行。

补充离线复核只取固定时间顺序最后200条，核对50组4/1/4/1及无重叠，得到r3包络88.056μs，各段11.6755/28.7730/15.9385/31.6040μs，与第一进程一致。该复核另存repeat2-tail-review.json，不改原failed报告，不放宽原工具断言，不挑快样本；未直接补造第二进程CANN设备倍率。下次测量应显式处理开始位置的部分调用并验证完整尾部，而不是靠总行数整除假设。
